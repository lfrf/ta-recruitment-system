## 1. Objective
The purpose of the meeting was to convert the requirements findings into a shared product backlog and confirm that the user stories reflected stakeholder needs identified earlier in the requirements work.

## 2. Inputs Reviewed
The team reviewed the following materials before and during the discussion:
- `requirements-findings.md`
- interview questions and interview record drafts
- prototype page plan and page copy draft
- first assessment report draft
- current backlog draft

## 3. Discussion Summary
The team agreed that the backlog should be derived directly from the requirements findings rather than treated as a separate document created independently.

The discussion was organised by stakeholder role:

### Applicant
The team agreed that the applicant side should focus on the minimum actions needed to support application submission. This included reusable profile maintenance, CV upload, vacancy browsing, vacancy detail viewing, role application, multi-role support, and application status visibility.

### Module Organiser
The team agreed that module organiser stories should support the full review workflow. This included vacancy creation, applicant list viewing, profile and CV review, decision update, and traceable decision recording.

### Admin
The team agreed that admin stories should focus on workload overview and visibility of overload risks, rather than advanced analytics in the first version.

### Cross-cutting quality stories
The team also agreed that some stories should apply across all roles, especially validation, status consistency, structured record keeping, and duplicate-data prevention.

## 5. Decisions Made
- All backlog items should be expressed as user stories in the format **“As a..., I want..., so that...”**
- The first usable version should focus on the end-to-end recruitment workflow rather than optional enhancements
- Advanced AI-like support should not be treated as a first-assessment priority
- Contributor involvement should be visible in the backlog evidence so that collaboration is clear
