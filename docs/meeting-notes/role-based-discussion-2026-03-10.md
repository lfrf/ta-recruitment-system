# Role-Based Discussion Notes

**Project:** TA Recruitment System  
**Date:** 2026-03-10  
**Format:** Team role-based discussion after the requirements workshop  
**Participants:** Yifu Feng, Yuzhang Wu, Chensiyuan Qing, Fuhe Huang, Tao Li, Mu Du  
**Recorded by:** Yuzhang Wu

## Purpose
This discussion was held to move from broad workshop findings into more concrete stakeholder viewpoints. Instead of discussing the system only in general terms, the team revisited the process from the perspectives of **Applicant**, **Module Organiser**, and **Admin** so that the later backlog would reflect role-specific actions.

## Discussion Focus
- clarify the responsibilities and pain points of each stakeholder;
- separate the core recruitment flow from later or optional ideas;
- identify which actions should belong to Applicant, MO, and Admin;
- prepare clearer user stories for the first backlog draft.

## Role-Based Findings

### Applicant viewpoint
- Applicants need vacancy information before deciding whether to apply.
- Repeated data entry should be reduced through a reusable profile.
- CV upload alone is not enough; the system should later support a more structured profile.
- Status visibility after submission is important.

### Module Organiser viewpoint
- MOs need vacancy posting and applicant review to be handled inside one workflow.
- Profile information and CV should be visible together during review.
- Decision recording should be consistent and traceable.
- Workload information may help avoid over-committed applicants.

### Admin viewpoint
- Admin mainly need workload visibility rather than a full scheduling system.
- Overload or conflict cases should be visible from accepted assignments.
- Data consistency matters more than advanced analytics in the early release.

## Early Decisions Taken
- The early release should focus on the recruitment route rather than later tutorial scheduling.
- Applicant browsing, application, MO review, and admin workload overview should remain central.
- Optional or advanced features should be recorded but not forced into the first working version.

## Resulting Impact
This discussion was used to refine the first story split across:
- applicant profile and application;
- vacancy posting and applicant review;
- admin workload monitoring;
- cross-cutting validation and consistency stories.
