# Requirements Findings

## Why we made this document
This document gives a short summary of the main needs we identified for the TA recruitment system. It is based on the stakeholder groups we focused on:
- Applicants
- Module Organisers (MO)
- Admin staff

This summary will help the team improve the backlog, support the prototype, and provide material for the report.

---

## Main Stakeholders

### Applicants
Applicants want a simple way to find TA opportunities, apply for them, and check their application status. They also need clear job information before they decide to apply.

### Module Organisers (MO)
Module Organisers need a clear way to post TA roles, review applications, and choose suitable applicants. They also need useful applicant information to support decision making.

### Admin Staff
Admin staff need to monitor TA workload, keep records, and check whether there are conflicts across different roles or modules.

---

## Main Needs by Stakeholder

### Applicants
- View available TA roles clearly
- See important job details before applying
- Create and manage a profile
- Upload CV and other basic information
- Apply for more than one role if needed
- Check application status easily

### Module Organisers (MO)
- Create and post TA roles
- View applicant information clearly
- Compare applicants more easily
- Accept or reject applicants in the system
- Check applicant workload when necessary

### Admin Staff
- View workload across applicants
- Keep recruitment records
- Check for conflicts or overload
- Search across different applicants, roles, or modules
- Get a simple overview of the whole process

---

## Early Findings
From the current requirement analysis, a few points seem especially important:

1. Applicants need the process to be simple and clear.
2. MOs need enough applicant information to make decisions quickly.
3. Admin staff need better visibility of workload and records.
4. Different users need different views of the same system.
5. The first version of the system should focus on core tasks, not too many extra features.

---

## Suggested Priorities for the Backlog

### High Priority
- Applicant profile
- TA job listing
- Job application submission
- MO job posting
- Application review and decision update
- Basic workload checking for admin

### Medium Priority
- Applicant filtering or sorting
- Better status tracking
- Search across roles or modules

### Lower Priority
- More advanced matching features
- More detailed reports or analytics
- Extra convenience features that are not essential for the first version
