## Questions and Answers

### Question 1
**Question:** How do you currently monitor the overall workload of TAs?  
**Answer summary:** It is usually checked manually through existing records or spreadsheets.

### Question 2
**Question:** When do you consider a TA to be overloaded?  
**Answer summary:** A TA is overloaded when they have too many accepted roles or conflicting commitments across modules.

### Question 3
**Question:** What summary information would help most?  
**Answer summary:** A clear table showing each TA, accepted jobs, workload, and possible risk flags would be most useful.

### Question 4
**Question:** What records should the system keep?  
**Answer summary:** Applicant status, accepted roles, and workload-related records should remain visible and consistent.

### Question 5
**Question:** What system failure would cause the biggest problem?  
**Answer summary:** Missing or inconsistent workload data would make allocation decisions unreliable.

## Key Findings
- Admin users need a clear workload overview
- risk or conflict cases should be visible early
- reliable records matter more than advanced analytics in the first version

## Pain Points
- manual workload checking is inefficient
- conflicts across modules are hard to identify quickly
- inconsistent records reduce confidence in decisions

## Candidate Requirements

### Functional
- The system shall provide an admin workload overview.
- The system should allow filtering by applicant or module.
- The system should flag possible overload cases.

### Non-functional
- Records should remain consistent across the system.
- The workload view should be simple and easy to interpret.
