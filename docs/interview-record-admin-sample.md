# Interview Record – Admin Stakeholder

**Project:** TA Recruitment System  
**Stakeholder role:** Admin  
**Interview type:** Semi-structured role-based discussion  
**Date:** 2026-03-10  
**Recorded by:** Group 27

## Summary of Discussion
The discussion suggested that admin users are mainly concerned with monitoring accepted TA workload across applicants and modules. In the current manual process, this information is often difficult to check because records are distributed across multiple spreadsheets or files.

Admin users want a simple overview that helps them identify workload conflicts or overload risks more quickly. They do not require advanced analytics in the first version, but they do value consistency, traceability, and ease of checking.

The team therefore concluded that the early version of the system should support a basic workload overview with enough structure to make records easier to review and maintain.

## Main Pain Points
- workload visibility is weak in the current process;
- records are difficult to verify when stored across multiple files;
- cross-module overload or conflict cases are not easy to identify quickly.

## Derived Requirements
- The system shall provide an overview of TA workload for admin users.
- The system should allow filtering by applicant or module.
- The system should highlight possible overload or conflict cases.
- The system shall preserve recruitment records in a consistent and traceable structure.

This record is intended as supporting evidence for the admin-related backlog and scope decisions.
