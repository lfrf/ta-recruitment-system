# First Assessment Brief Report Outline

## Page 1: Project Context and Scope
- Briefly explain the current manual TA recruitment situation.
- State the purpose of the proposed system.
- Identify the three main stakeholder groups:
  - `TA Applicant`
  - `Module Organiser (MO)`
  - `Admin`
- Define what is in scope and what is out of scope.
- State the technical constraints:
  - Java or Servlet/JSP only
  - text-based storage only
  - no database

## Page 2: Fact-Finding Techniques
- Describe the fact-finding techniques used:
  - background reading
  - interviewing
  - document analysis
- For each technique, state:
  - why it was chosen
  - how it was used
  - what it revealed
- Summarise how the findings informed the backlog.

## Page 3: Requirements and Backlog Formation
- Present the main functional requirements.
- Present the main non-functional requirements.
- Show how requirements were transformed into epics and user stories.
- Explain how acceptance criteria were defined.

## Page 4: Prioritisation and Estimation
- State that `MoSCoW` was used for prioritisation.
- Explain the prioritisation basis:
  - business value
  - feasibility
  - risk
  - assessment timeline
- State that story points were used for estimation.
- Explain the scale used, for example `1, 2, 3, 5, 8`.
- Give 3 to 5 concrete examples.

## Page 5: Iteration Planning
- Explain how the backlog was divided into iterations.
- Show the objective of each iteration.
- Highlight incremental delivery and feedback.
- Explain how GitHub and meetings support Agile management.
- End with a short conclusion on why the plan is realistic.

## Supporting materials outside the 5-page limit
- Interview questions
- Interview records
- Workflow analysis notes
- Prototype feedback
- Other evidence used to support the report
